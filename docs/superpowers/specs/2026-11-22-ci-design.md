# GitHub Actions CI 设计

## 目标

push / PR 到 main 自动运行全部后端测试；README 顶部挂 status badge。

## Workflow

`.github/workflows/ci.yml`：

- 触发：`push: branches: [main]` + `pull_request: branches: [main]`
- `runs-on: ubuntu-latest`
- Python 3.12（对齐本地 .venv 3.12.16），启用 pip 缓存
- 步骤：checkout → setup-python → `pip install -r requirements.txt` → `sudo apt-get install -y libgl1`（opencv-python 4.10 非 headless，无头 Linux 缺 libGL；保守方案不动 requirements）→ `python -m pytest backend/tests -q`

## 注意事项

- `requirements.txt` 已含 pytest / httpx，无需额外 dev 依赖
- rawpy 0.28 / pillow 13.0 / numpy 2.5 均有 manylinux wheel，Linux 可装
- `data/` 已 gitignore，测试用 tmp 目录，无需 fixture
- **Linux 兼容性风险**：本地 293 个测试在 macOS 全绿；若 CI 实测有 Linux-only 失败（如路径/face engine 差异），允许在 yml 中用 pytest deselect 显式跳过并在注释写明原因，但不允许为此改动产品代码
- README.md 顶部（标题下、正文前）加 badge：
  `[![CI](https://github.com/yaohl0911/photo-picker/actions/workflows/ci.yml/badge.svg)](https://github.com/yaohl0911/photo-picker/actions/workflows/ci.yml)`

## 验证方式

agent 无法推送验证 workflow 真跑（推送权在 lead）；agent 负责：yaml 语法自检（python yaml 解析）、步骤逻辑核对、README badge 链接核对。真实 CI 首跑由 lead 推送后监控并回报。

## 写域（agent-ci 独占，并行纪律）

`.github/workflows/ci.yml`, `README.md`（仅 badge 相关改动）

其他 agent 正在并行修改不相交文件（backend/、frontend/dist/）——绝不触碰上述写域之外的任何文件，不执行任何 git 写操作（commit/stash/checkout/reset 一律禁止，允许 git status/diff 只读）。
